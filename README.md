#### Сравниваются три реализации:
1) naive: наивная версия, с расчетом одной точки за цикл
2) arrays: версия с расчетом восьми точек за цикл при помощи массивов
2) avx: версия с расчетом восьми точек за цикл с использованием интринсиков

Измерение времени исполнения программы производится с помощью инструкции rdtsc().
За один тест считаются 500 точек. Всего 4 теста для прогрева и 7 рабочих.
Затем высчитывается среднее значение и стандартное отклонение для каждого случая.
Получившиеся замеры представлены в двух таблицах: с абсолютными значениями тактов, а также в виде отношения - коэффициента, отображающего, насколько ускорилась программа по сравнению с неоптимизированной версией.

## Анализ дизассемблера, полученного с помощью godbolt.org

### Анализ версии arrays при компиляции g++ с -O2 против -O3

В случае версии с массивами при компиляции с помощью g++ оптимизация -O2 оказалась в 6 раз быстрее оптимизации -O3.
Компилятор при опции -O2 смог применить векторизацию и использовать SIMD-инструкции. Однако в случае
с -O3 компилятор использует множество скалярных операций и обращений к стеку.
Это может быть связано с применением более агрессивных оптимизаций, таких как Loop Unrolling. Код разрастается, и из-за этого компилятор не может применить векторизацию.

### Анализ версии avx при компиляции clang++ с -O3 против -Ofast

Разберемся, почему при компиляции clang с флагом оптимизации -O3 код ускорился в 14.18 раз, а с флагом -Ofast аж в целых 17.62 раз! Для этого посмотрим дизассемблированный код с помощью утилиты objdump.

Однако, код функций MandelbrotIntrinsics512 и MakeTests абсолютно одинаков.

<p align="center">
    <img src="assets/objdump_same1.png" width="75%">
</p>

Откуда же тогда ускорение?

В версии, скомпилированной с флагом оптимизации -Ofast есть только одно отличие - функция set_fast_math.

Что же она делает?

Она использует инструкции **stmxcsr** и **ldmxcsr**, считывающие и загружающие содержимое регистра MXCSR соответственно.

<p align="center">
    <img src="assets/set_fast_math.png" width="75%">
</p>

Управляющий регистр MXCSR (SIMD Floating-Point Control/Status Register) предназначен для маскирования/демаскирования SIMD-исключений, управления режимом округления, а также включения режима сдвига к нулю.
Что же именно меняет эта функция?

Для этого обратимся к флагам, которые устанавливает этот регистр, меняя поведение сопроцессора: 

<p align="center">
    <img src="assets/mxcsr.png" width="75%">
</p>

Итак, функция выставляет флаг FZ (Flush to zero) и DAZ (Denormals are zeros).

Таким образом, процессор отбрасывает денормализованные числа, считая их нулями, и уменьшает время вычислений.
